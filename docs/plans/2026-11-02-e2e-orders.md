# Electron 行为测试实施单

子代理只按本单写测试与 fixtures，不负责修改产品功能、调整设计或自行决定通过标准。主代理负责运行、截图 review、失败定位和复验。

## 1. 隔离夹具与启动器

新增 `fixtures/notes-demo/`：

- `首页.md`：含中文 H1/H2、任务列表、引用、表格、代码块、`[[目录/笔记]]`、`[[同名]]`、`[[不存在]]`、本地图片 `![](assets/pixel.png)`。
- `目录/笔记.md`：含 `[[首页]]` 和不同正文。
- `a/同名.md`、`b/同名.md`：用于同名消歧。
- `assets/pixel.png`：合法 1x1 PNG。
- `已有页面.html`：含安全静态标题、段落和内联样式，用于已有 HTML 预览/源码切换。

Playwright 每个测试复制该目录到 `app/.runtime/e2e/<test>-<uuid>/workspace`，运行数据放在同级 `runtime`。不得直接修改 fixtures 原件。

启动前写 `runtime/state/workspace-state.json`，内容使用现有 `createDefaultWorkspaceUiState(workspaceAbsolutePath)` 形状，使 `workspace.restore()` 自动打开副本。用 `_electron.launch({executablePath: app/node_modules/electron/dist/electron.exe,args:['.'],cwd:app,env:{...process.env,MARKDOWN_LITE_USER_DATA:runtime}})`，先执行生产 `npm run build`。记录 `firstWindow` 和 `#workspace-shell` 可见的时间。

捕获 `pageerror`、renderer console.error 和 main process 日志；除明确断言的错误场景外，测试结束不得有未解释异常。每个测试结束保存 `app/test-results/<test>/screenshot.png` 与 `result.json`（启动 ms、RSS、断言结果）。失败保留 trace，成功不保留大 trace。

## 2. 新应用行为用例

文件：`app/e2e/editor-workspace.spec.ts`。每个用例独立 runtime/workspace。

### E1 启动与真实文件树

- 自动恢复工作区，标题为 Markdown Lite Studio。
- 文件树出现 `首页.md`、`目录/笔记.md`、`a/同名.md`、`b/同名.md`、`已有页面.html`。
- 打开 `已有页面.html`，iframe 有静态内容，切到源码出现原始 HTML；不能执行其中的脚本。

### E2 中文编辑、预览、撤销重做和查找

- 打开 `首页.md`，`.cm-content` 可见，iframe 含标题/任务/表格/代码/图片。
- 点击编辑器，用 `keyboard.insertText` 输入独立中文标记；预览在 1.5s 内出现相同文本。
- Ctrl+Z 后标记消失，Ctrl+Shift+Z 后恢复；选区和光标仍可用。
- 点击 `#find-in-document`，搜索 `首页`，有匹配 UI。
- 保存后读取副本 `首页.md`，包含标记，dirty 消失；再等自动保存场景验证默认开启。

### E3 新建、重命名、反链与图谱

- 点击 `#new-note`，modal 输入目录 `目录`、文件名 `新建.md`，确认后真实文件存在并打开。
- 编辑器输入 `# 新建\n\n[[首页]]`，保存；打开 `首页.md`，反链面板出现 `新建.md`。
- 点击 `#toggle-graph`，图谱有真实节点 `首页.md`/`新建.md` 和边；无不存在的预设节点。点击节点可打开对应笔记。
- 重命名 `目录/笔记.md` 为 `目录/改名.md`，确认；原 `首页.md` 中 `[[目录/笔记]]` 更新为 `[[目录/改名]]`，`[[同名]]` 不变且结果显示歧义跳过说明。打开改名文件成功。

### E4 图片粘贴与恢复

- 通过页面内 DataTransfer/ClipboardEvent 把 `pixel.png` 的 File 粘贴到当前 Markdown 编辑器；不得使用 Node 直接改产品状态。
- 文档插入真实 `assets/<sha256>.png` 引用，文件存在且内容与像素一致；嵌套文档使用正确 `../assets` 相对路径。
- 重启同一 runtime，图片仍能显示，不是 blob 临时地址。

### E5 主题、布局、HTML 预览与导出

- 点击 `#toggle-theme-panel`，修改正文宽度、字号、行距、背景、标题/目录/侧栏配置；iframe 的 computed style/CSS 变量同步变化，根布局同步。
- 在 main process 仅测试进程内替换 `dialog.showSaveDialog`，返回副本目录下 `导出.html`；点击 `#export-html`。
- 真实导出文件存在，无脚本，本地图片为 data URI；导出的 CSS/正文与 iframe srcdoc 使用同一渲染结果。
- 修改 Markdown 后显示未导出修改；再次导出后标记清除。
- 重新打开导出的 HTML，应用内可预览并可看源码。

### E6 外部修改、保存失败和缺失链接

- 打开文档并制造未保存修改；用 fs 在外部写入不同内容，等待 conflict，手动保存和自动保存均不得覆盖外部文本。
- 点击重新加载并确认，外部文本进入编辑器，conflict 清除。
- 外部删除文件，出现 missing；保存被阻止。
- `[[不存在]]` 在预览和图谱中有 missing 标识，点击不会创建文件。
- 保存目标为只读目录或注入写入失败时有清晰错误，不伪报已保存。

### E7 重启恢复

- 打开两个笔记，编辑并保存，修改主题/布局，切换活动文档。
- 关闭 Electron，使用相同 runtime 重新启动。
- 工作区、打开文档、活动文档、主题布局恢复；中文内容不丢失。
- 撤销历史不要求跨重启恢复。

### E8 启动与资源测量

- 记录进程启动到 firstWindow 和 `#workspace-shell` 可见的毫秒数。
- 用 main `process.memoryUsage().rss` 记录启动稳定后 RSS；再打开 10 个小文档测量一次。
- 输出 JSON 与简短文本到 `app/test-results/performance.json`，只报告实测值，不写“更快/更轻”的结论。

## 3. MarkText 对照用例

文件：`app/e2e/marktext-compare.spec.ts`。

程序：`reference/marktext-win-x64-0.23.0/marktext.exe`。使用独立笔记副本和 `--user-data-dir <runtime>`，禁止默认用户目录。只测试已经由静态证据确认存在的通道，不读 GitHub 源码。

1. **打开与渲染**：以 `--read-only <workspace/首页.md>` 启动，编辑器出现相同中文标题、任务、表格、代码与图片；记录 MarkText 是 WYSIWYG 内联预览，新应用是独立 HTML 预览，属于主动设计差异。
2. **真实保存**：另一副本不使用 read-only，在 Muya 编辑器追加独立文本并 Ctrl+S，读取文件确认。比较两者均真实写盘；新应用额外有 baseHash CAS，不把该差异写成 MarkText 通过。
3. **HTML 导出**：通过 main `webContents.send('mt::show-export-dialog','styledHtml')` 打开已知导出对话框，测试进程内替换保存对话框目标为 `marktext-export.html`，完成导出。记录 MarkText 本地图片是 file URL 而非 data URI（与静态证据一致），新应用是 data URI 单文件。比较预览主题与导出主题的差异，不强行要求相同。
4. 将实际观察写入 `app/test-results/marktext-compare.json`，无法自动操作的步骤保持 unknown，不得伪报通过。

## 4. 主代理验收后处理

- 主代理运行全部 E2E，查看截图和真实导出文件。
- 失败时先定位产品 bug、测试 bug或主动差异；产品问题只发精确修复单给实现子代理。
- 全部通过后运行 `npm run package`，再用 `dist/win-unpacked/markdown-lite-studio.exe` 做一次启动冒烟。
- 最终结果、截图路径、性能数字、对照差异和未验证项写入 evidence；不得只凭测试存在就宣布通过。
