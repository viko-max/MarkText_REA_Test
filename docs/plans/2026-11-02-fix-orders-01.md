# 修复单 01：真实 E2E 发现的问题

子代理只按本单修改点名文件与测试，不做其他设计或重构。

## 1. Windows 重做快捷键（产品 bug）

文件：`app/src/renderer/src/editor/keymap.ts`

- 从 `@codemirror/commands` 额外导入 `redo`。
- 增加绑定 `Ctrl-Shift-z`，调用经过 `guardCommand` 包装的 `redo`。
- 保留现有 `Mod-y` 和全部 IME guard，不替换 historyKeymap。
- 在适当的编辑器单元测试中加入 Windows 风格绑定断言；E2E 以 Ctrl+Z → Ctrl+Shift+Z 的真实结果为最终验收。

## 2. 分屏状态持久化（产品 bug）

文件：`app/src/shared/contracts.ts`、`app/src/shared/validation.ts`、`app/src/renderer/src/main.ts`、相关契约测试。

- `ViewMode` 改为 `'edit' | 'preview' | 'split' | 'html'`。
- `VIEW_MODES` 同步加入 `split`。
- `persistedViewMode` 直接返回传入的 `edit|preview|split`，不再把 split 降为 preview。
- `shellViewModeOf` 对 edit/preview/split 原样返回；html 仍只用于 HTML 文件，不进入 Markdown 持久化。
- 更新测试：split 的 state validation 通过；E3 重命名后仍是 split；E7 重启后仍是 split。

## 3. 文件系统错误可读性（产品改进）

文件：`app/src/main/ipc.ts`、`app/tests/main-ipc.test.ts`。

在 `toFailure` 的通用 `console.error` 前处理 Node errno：

- `EPERM|EACCES|EROFS` → `ipcFail('forbidden','file access denied',{reason:code})`。
- `ENOSPC` → `ipcFail('too_large','not enough disk space',{reason:code})`。
- `EBUSY` → `ipcFail('conflict','file is busy',{reason:code})`。

保留 AppError/WorkspacePathGuardError 的既有优先级，不暴露堆栈。通过 fake service 让 handler 抛出上述 errno，验证 IPC code/message/details，不断言平台 chmod 行为。

## 4. 修正测试预期（测试 bug，不改产品）

文件：`app/e2e/editor-workspace.spec.ts`

- `[[同名]]` 与被重命名的 `目录/笔记.md` 无关，不应产生 skippedReferences；删除“状态栏必须出现同名歧义”的错误断言。
- 保留断言：无关 `[[同名]]` 原文不变，真实目标 `[[目录/笔记]]` 正确更新，结果显示更新的文件数和引用数。
- 新增第 2 项所述 split 断言。
