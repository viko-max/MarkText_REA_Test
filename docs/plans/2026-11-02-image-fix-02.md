# 修复单 02：图片加载兼容性

子代理只按本单复现、修改和验证，不做范围外设计。

## 已定位问题

`app/src/renderer/src/render/resources.ts` 的 `resolveWorkspaceImagePath()` 在解码后遇到任何 `\` 都返回 `invalid_separator`。Windows/MarkText 笔记中常见的 `![](assets\pixel.png)` 因而无法进入图片读取流程。既有 E2E 只覆盖 `/`，所以未暴露。

## 1. 先补失败复现

新增单元与 E2E 断言，先证明修复前行为：

- `resolveWorkspaceImagePath('目录/笔记.md','../assets\\pixel.png')` 当前返回 reason；修复后应返回 `{path:'assets/pixel.png'}`。
- `resolveWorkspaceImagePath('首页.md','assets\\中文 图片.png')` 修复后返回 `{path:'assets/中文 图片.png'}`。
- `../outside\\secret.txt` 仍必须阻止越界；`C:\\secret.png` 与 `C:/secret.png` 仍按 absolute_path 拒绝，不放宽工作区边界。
- 真实预览中 `![](../assets\\pixel.png)` 的 iframe img 必须是 data URI 且 naturalWidth>0。
- 用本地回环 HTTP server 提供同一 PNG，Markdown 使用 `http://127.0.0.1:<port>/pixel.png`；预览应为 external 且 naturalWidth>0，导出依赖列 remote。不得访问外网。

## 2. 限定产品修复

文件：`app/src/renderer/src/render/resources.ts`

- 在 `resolveWorkspaceImagePath` 中，解码后仅把路径分隔用的 `\` 统一为 `/`，再做段遍历、越界检查和 `isWorkspaceRelativePath`。
- 不改变 absolute path 拒绝规则，不允许 `..` 越过工作区根，不改变远程/data URL/格式/大小校验。
- 注释改为说明 Windows 相对路径会归一成 POSIX，而不是拒绝。

文件：`app/src/renderer/index.html` 仅在远程 HTTP 复现证明父 CSP 阻断时修改：

- 若 iframe 内远程图片因父 CSP 失败，根 `img-src` 增加 `https: http:`，保留其余 CSP 不变；若已通过，不改。

## 3. 回归与交付

- 新增上述单元与真实 Electron 图片场景，确认修复前失败、修复后通过。
- 运行 `npm test`、`npm run build`、`npm run test:e2e`，全部通过。
- 运行 `npm run package`，用打包 EXE 对 Windows 反斜杠图片做一次启动预览验证。
- 记录修复前后的真实结果，不把仅解析路径成功当作图片已显示。
