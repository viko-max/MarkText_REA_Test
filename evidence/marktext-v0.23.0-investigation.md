## 1. Markdown 编辑与实时预览

**问题**：内容、视图、源码模式、输入和撤销怎样衔接？

**证据**：

- `out/renderer/assets/index-mApCbCvT.js:159651`：Muya 使用 JSON 状态；`159713-159789` 在下一帧合并操作；`159753-159760` 序列化 Markdown。
- 同文件 `198836`：编辑器与 CodeMirror 源码视图互斥挂载；`165043-165055` 模式切换通过整篇替换并保留历史。
- 同文件 `108005-108176`：浏览器 Selection 与块/偏移映射；`108695-108752` 中文组合输入补丁；`159807-159959` 撤销栈与分组。
- 同文件 `195856-195867`：内容变化后派生 TOC、词数等；`164624-164757` 跨模式光标使用哨兵字符串。

**结论**：MarkText 的“实时预览”主要是所见即所得块树，不是独立预览面板。Markdown 是持久化形式，编辑器另有 JSON 状态。中文输入、选区和撤销有大量应用自有处理；通用依赖包括 CodeMirror、marked、ot-json1、jsdiff。

**实现影响**：新应用采用 CodeMirror 的统一文档模型和成熟 IME/选区/撤销能力，Markdown 字符串为唯一持久真相；预览独立渲染并延迟派生计算。主动简化块树、OT、哨兵光标和三套历史，避免每帧全量序列化。

**未知**：MarkText 在真实 Windows 中文输入法与快速模式切换下的竞态未验证；新应用须独立测试中文组合输入和撤销。

## 2. 文件、保存与图片

**问题**：文档如何打开、保存、判脏、自动保存、处理外部变化与图片？

**证据**：

- `out/main/index.js:17440-17489`：保存进入 `handleResponseForSave`；`3957-3962` 编码和换行处理；`3805-3824` 原子写与 Windows 重试。
- `out/main/index.js:16904-16949`：按 `owner:tabId` 串行写及只读 epoch 栅栏。
- `out/renderer/assets/index-mApCbCvT.js:190906-190937`：修改状态由历史指针派生；`189939-190958` 自动保存去抖。
- `out/main/index.js:4003-4287`：chokidar 监视、读序号、自写忽略；渲染端 `191080-191135` 外部变化处理。
- `out/renderer/assets/index-mApCbCvT.js:161975-162104` 图片异步占位与替换；`195183-195231` 落盘策略；`188748-188769` 内容哈希命名。

**结论**：文档原子写和写队列值得复现。参考程序保存前不校验磁盘版本，冲突只阻止自动保存，手动保存仍可能覆盖外部改动。图片最终写入真实文件并用相对路径或 file URL 引用。

**实现影响**：每文档保存 `baseHash`、磁盘哈希和显式状态机；原子写前执行 compare-and-swap，冲突同时冻结手动与自动保存。图片先写 `assets/<hash>.<ext>`，成功后才插入统一正斜杠相对引用。使用工作区恢复文件保存打开状态。

**未知**：参考程序的重命名历史边界、尾部换行伪冲突等未做动态确认，不作为新应用行为标准。

## 3. HTML 导出与主题

**问题**：导出入口、正文、资源、页面结构和主题怎样组成？

**证据**：

- `out/main/index.js:17727-17729` 导出入口只通知渲染端；`17311-17353` 主进程最终写文件。
- `out/renderer/assets/index-mApCbCvT.js:195440-195531` 渲染端导出编排；`193560-193591` 包装正文；`166220-166252` HTML 模板与样式顺序。
- 同文件 `107174-107208` 本地图片转 file URL；`166005-166012` DOMPurify；`194673-194712` 导出 CSS。
- 同文件 `84893-85019` 编辑预览主题包在 `@media not print`；`194684-194696` 导出主题独立选择。

**结论**：HTML 由渲染进程生成、主进程落盘。正文不是纯字符串转换，还依赖真实 DOM 和图形渲染器。预览主题与导出主题是两套系统；图片默认不内联，单文件离线完整性有限。

**实现影响**：保留两阶段导出，但新应用只实现可控 Markdown 子集，不引入 Muya 和大型图形依赖。预览和导出必须共享同一 HTML 生成器、CSS 变量与资源解析；本地图片嵌入 data URI，远程资源明确标为外部依赖。用内容签名区分“未导出修改”和已写 HTML 文件。

**未知**：参考程序的动态图形、打印 CSS 层叠和异常主题输入不在本轮复现范围。
